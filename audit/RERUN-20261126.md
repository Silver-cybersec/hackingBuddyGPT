## 2. 架构

结论：一个无入站端口的 CLI 进程。信任边界在「操作者配置的模型上游」和「操作者指向的目标」两侧都向外开放；进程内没有单独的鉴权层。

组件与数据流：

1. `wintermute`（`cli/wintermute.py:8-20`）用 `usecases/__init__.py` 导入已装饰的用例，再 `asyncio.run`。
2. 配置四层覆盖，后写覆盖先写：环境变量、`.env`、`--config` JSON、命令行（`utils/configurable.py:769-837`）。`llm.api_key` 标了 `secret=True`。
3. 用例循环在 `AutonomousUseCase.run`（`usecases/usecase.py:69-99`）或 `WebAPITesting.run`。每轮把历史交给 `LiteLLM.get_response`（`utils/llm.py:56`）。
4. 模型若返回命令或工具调用，能力对象执行：
   - Linux 提权：持久 SSH shell，`SSHInteractiveConnection`（`utils/connectors/ssh_interactive_connection.py`）。
   - Windows 提权：`PSExecConnection` → `cmd.exe /c`（`utils/connectors/psexec.py:34`）。
   - Web 带 shell／高级：Fabric `SSHConnection` 到单独的 `kali_conn`（`usecases/web/with_shell.py:28`，`advanced.py:28`）。
   - AD：`AsyncSSHConnection` 上并行执行命令（`utils/connectors/async_ssh_connection.py`），规划器与无记忆执行器在 `usecases/ad/`。
   - 纯 Web：`HTTPRequest` 从本进程发请求（`capabilities/http_request.py`）。
5. 限额默认 100 轮、0 token（不限）、10 美元、0 秒（不限时长）（`utils/limits.py:30-33`）。策略类再被 `max_turns` 默认 10 收紧（`strategies.py:71`）。
6. 日志是本地 `logs/log-<时间>.jsonl`（`utils/log_storage.py:119`）。没有远程日志后端；文件头注释写明已去掉旧的 SQLite／远程后端（`utils/logging.py:9`）。

已注册用例名（装饰器去掉类名后缀 `UseCase`）：`MinimalPrivEscLinux`、`MinimalToolCallPrivEscLinux`、`PrivEscLinux`、`PrivEscWindows`、`ExPrivEscLinuxLSE`、`WebTestingWithExplanation`、`WebTestingWithShell`、`AdvancedWebTesting`、`WebAPITesting`、`AD`。

权限与绕过，只写已读到的：

- 模型输出没有命令白名单。目标回显进入下一轮提示（`strategies.py:81-102`），目标可以影响后续命令。这是间接提示注入的数据流，本单未做注入实验。
- 子代理只能拿到父代理显式交出的能力（`usecases/agents.py:220-230`）。总结轮使用 `Limits(max_rounds=0, max_cost=0)`（同文件 276），注释写明这一轮不占额度。
- `task_solved` 的成功在工具调用版里对照真实命令输出（`usecases/priv_esc/minimal_linux_privesc_tool_calling.py:15-37`）。策略版用 `check_command_success`。本单未跑命令，未验证检测器的误报。
- 本进程不监听端口。暴露面是出站：模型 API、SSH/445、HTTP，以及操作者本机的 Docker CLI（仅 `benchmark_privesc.py`）。

故意能力（产品目的，不单列为缺陷）：对配置目标做命令执行、提权、HTTP/API 测试、AD 假设失陷。AD 默认场景文案包含口令喷洒和 `impacket`／`hashcat` 的用法说明（`usecases/ad/templates/scenario.md`）。仓库不附带可被攻破的 Web 或系统靶场；Linux 提权靶场在另一个仓库 `ipa-lab/benchmark-privesc-linux`，本单不审那个仓库。

## 3. 代码安全

结论：对部署者的主要风险是机密和命令回显离开本机，以及文档上的出口开关没有接到代码。仓库里没有「故意留个洞让学生打」的关卡源码。下面高／中／低只计真实边界问题。动态利用均未做。

### 高

- **HB-01 机密进入模型与日志。** 提权模板包含 `${conn.password}`（`usecases/priv_esc/_base.py:22`，`linux_privesc.py:50`，工具调用版 `minimal_linux_privesc_tool_calling.py:96`）。口令字段不是 secret；配置快照只脱敏 `llm.api_key`（`utils/configurable.py:754-766`）。回显回到历史再发给模型。JSONL 保存消息正文（`utils/log_storage.py:129`）。
- **HB-02 `llm.api_base` 未传入 litellm。** `utils/llm.py:143` 将该参数注释掉。README 第 123–127 行仍写默认端点是 OpenRouter、改 `api_base` 即可换上游。`benchmark_privesc.py:259-262` 已承认这一点，并改用 `OLLAMA_API_BASE`。实际请求落点未实测。

### 中

- **HB-03** asyncssh 两处 `known_hosts=None`（`ssh_interactive_connection.py:71`，`async_ssh_connection.py:45`）。Fabric 连接器没有对应设置；其库默认策略未核实。
- **HB-04** `HTTPRequest` 拼接 `host + path`（`capabilities/http_request.py:67-77`）。设置 `CLIENT_HTTP_PROXY` 或 `CLIENT_HTTPS_PROXY` 时关闭 TLS 校验（同文件 24-32）。
- **HB-05** `lse.sh` 跟踪 GitHub `releases/latest`，无校验和，在目标上执行（`usecases/call_usecase_from_usecase.py:36-38`）。
- **HB-06** Web 提示要求不要确认（`usecases/web/_base.py:22-24`），默认主机 `http://localhost`（同文件 36）。AD 默认场景目标为 `192.168.122.0/24`（`scenario.md:9`）。默认限额见 `utils/limits.py:30-33`。
- **HB-07** RAG 把本地 Markdown 交给未设置 `base_url` 的 `OpenAIEmbeddings`（`utils/rag.py:28-31`）。端点 URL 未核实。仅在安装 rag extra 且传入 `rag_path` 时走到。
- **HB-08** 镜像以 root 运行，基础镜像与发布标签无 digest（`Dockerfile:1-7`，`publish-docker.yml:36-40`）。无宿主挂载。`.dockerignore` 排除 `.env`。层未拉取。
- **HB-09** 锁内版本落在 OSV 公告区间。与默认安装最直接的是 `certifi` 2026.7.22。详见 `audit/supply-chain.md`。可利用性未按调用路径证实。

### 低

- **HB-10** 示例口令 `trustno1`／用户 `lowpriv`（`.env.example:34-36`）。基准脚本把 API key 和口令放进子进程 argv（`benchmark_privesc.py:239-244`）。不是本项目的线上密钥。全库未发现私钥或云长期密钥。
- **HB-11** PSExec `create_service` 后本仓库没有拆除；单次超时 2 秒（`utils/connectors/psexec.py:20-35`）。服务是否残留未核实。
- **HB-12** `local_shell` 对 tmux 会话无过滤送键（`utils/connectors/local_shell.py:66`），但已注册用例的 `conn` 不是这个类型，当前 CLI 选不中它。

其它已读、不单列：

- Mako 模板是仓库内的固定字符串；`${history}` 是变量插入，没有把不可信字符串再编译成模板。
- 没有 `eval`／`exec` 执行模型输出。模型输出作为 shell 命令或 HTTP 参数，这是上面的执行面。
- 日志目录在 `.gitignore`。文件创建没有显式 `chmod`。
